# 开发路线

目标：把现在的原型做成一款可以发布、玩家之间真正共享残响的游戏。每个阶段都能单独交付和试玩，后一阶段建立在前一阶段的验收之上。

## 阶段 0：迁入代码仓库（已完成）

- [x] 单文件原型拆分为模块：`core`（纯逻辑）/ `editor` / `play` / `sim`
- [x] 核心逻辑改为纯函数，可在 Node 里测试
- [x] 零依赖开发服务器、单文件打包
- [x] 单元测试 + 浏览器冒烟测试
- [x] 设计文档、数据格式、开发约定

## 阶段 1：把"工具"和"游戏"分开（已完成）

- [x] 两个入口：`index.html` 是游戏，`editor.html` 是剧情编辑器 + 试玩 + 推演
- [x] 游戏不再引用编辑器代码，改用事件通知；打包后游戏 72 KB、编辑器 133 KB
- [x] 剧情数据改为 JSON 文件（`stories/fog-town.json`），编辑器可以下载为文件、从文件导入
- [x] 剧情数据加格式版本、版本号和结构校验，加载出错时给出具体的中文原因
- [x] 模拟可以填随机种子，结果完全可复现
- [x] 核心逻辑代码可读性整理（`src/core/` 全部展开并加注释）
- [ ] 界面模块的可读性整理：随阶段 2 的改动逐步进行

**验收**：游戏入口里看不到任何编辑功能；用导出的 JSON 能完整还原剧情；同一种子下模拟结果完全一致。

## 方向调整：正式游戏改用 Godot 开发（进行中）

网页部分保留为剧情编辑器（编写、检查、推演）和规则的参考实现；正式游戏用 Godot 4.5 + GDScript 开发，面向电脑、手机和网页。

- [x] 提取游戏机制：`docs/MECHANICS.md`，网页版规则抽成纯逻辑的 `src/core/run.js`
- [x] 一致性用例 `tests/vectors/`：网页版和 Godot 版共用
- [x] Godot 核心规则移植（story / run_engine / save_codec），无界面测试全部通过
- [x] Godot 可玩版本：标题画面、横版移动、物件互动与菜单、飞过的残响（相信 / 点赞）、死亡与刻残响、记忆笔记、自动存档、暂停与设置、键盘 / 手柄 / 触屏
- [x] 中文字体子集（思源宋体 + 霞鹜文楷），导出预设（Windows / macOS / Linux / Web）
- [x] 持续集成：每次推送跑两边的测试
- [ ] 在真机上试玩：手机触屏手感、界面大小
- [ ] Android / iOS 导出配置（签名、图标、启动画面）

## 阶段 2：完整的单机游戏体验（在 Godot 版里继续）

- [x] 标题画面：开始 / 继续 / 重新开始（需确认）/ 设置，全键盘操作
- [x] 自动存档：每次行动后保存，回来能接着当前轮回和跨轮记忆；剧情更新后只保留记忆
- [x] 暂停菜单（Esc）：继续、设置、回到标题
- [x] 设置：文字速度（慢 / 中 / 快 / 立即显示）、动态效果（跟随系统 / 完整 / 减少）
- [x] 对话系统：场景正文一行一句，【名字】开头是台词，带说话人名字，按空格或点击翻页（网页版和 Godot 版都支持，分句规则两边共用测试）
- [ ] 人物和场景美术：从程序绘制过渡到插画图层（背景 / 中景 / 人物 / 前景）
- [ ] 音效与音乐：环境音、钟声、互动音效、死亡音效，带音量设置
- [ ] 转场与反馈：死亡演出、记忆碎片获得演出、残响刻下演出
- [ ] 手机触屏和手柄操作（触屏方向键已有，菜单还需要适配）
- [ ] 线索笔记本：查看已知线索、已见过的结局、轮回统计

**验收**：不懂规则的新玩家能在 30 分钟内自己玩通第一章，并说出"残响是怎么回事"。

## 阶段 3：残响联网

这是游戏的核心卖点，也是第一次需要服务器。

- [ ] 后端服务：残响写入、按场景拉取、点赞，带简单的防刷限制
- [ ] 推送策略：新残响和高赞残响混合，保持一定比例的谎言
- [ ] 世界线分组：玩家分到不同世界线，关键答案按世界线随机，残响只在同世界线流通，防止攻略外泄
- [ ] 残响内容管理：模板 + 词库输入（只能用见过的词），敏感词过滤，举报
- [ ] 冷启动：预置残响池，对玩家不标明来源
- [ ] 回响反馈：有人因为你的残响通关或踩坑时通知你

**验收**：两台设备上的玩家能看到彼此的残响和点赞；切换世界线后答案确实不同。

**待决定**：后端技术选型（例如 Cloudflare Workers + D1、Supabase，或接入 neowow 平台的接口）。

## 阶段 4：内容生产

- [ ] 写完整的"真相文档"：世界观、人物、秘密
- [ ] 第一章扩展到 40–60 个节点、3–4 个结局
- [ ] 第二、三章
- [ ] 用推演工具调平衡：每章通关中位局数、每个劝退点的死亡占比设定目标值

**验收**：推演显示第一章通关中位局数在 4–8 局之间，没有任何一个节点占失败的 40% 以上。

## 阶段 5：AI 辅助创作

- [ ] 从真相文档自动拆出线索碎片
- [ ] 为每条线索生成"看起来像但是错的"变体，用作预设假残响
- [ ] 根据推演结果给出建议：哪里太难、哪里该加残响
- [ ] 玩家共创支线：简化版编辑器 + 自动校验 + 审核上线

## 阶段 6：发布

- [ ] 打包为 PWA，可安装、可离线
- [ ] 数据埋点：每个节点的到达率、死亡率、残响的相信率与准确率
- [ ] 部署（静态托管 + 后端），上架 neowow 市场或其他平台
