# 游戏机制

这份文档描述游戏规则本身，与实现语言无关。网页版（`src/core/run.js`）和 Godot 版（`godot/scripts/core/run_engine.gd`）都按它实现，并且都要通过 `tests/vectors/` 下的一致性用例。改规则时，按这个顺序：先改这份文档，再加或改用例，最后让两边的实现都通过。

剧情数据的字段见 [剧情数据格式](STORY_FORMAT.md)。

## 1. 两层状态

| 层 | 内容 | 什么时候清空 |
|---|---|---|
| 跨轮进度 | 已知线索 `know`、第几轮 `runs`、累计用时 `total`、轮回记录 `history`、起点 `startAt` | 只有玩家选择"重新开始"时 |
| 本轮状态 | 所在节点 `node`、足迹 `path`、本轮用时 `t`、背包 `items`（道具 → 数量）、货币 `money`、用过的一次性选项 `used`、本轮得知的线索 `runClues`、信念 `belief`、相信过的残响 `believed`、结局 `end`、最后一次选择 `lastChoice`、死前得知的新线索 `newDeathClue` | 每一轮开始时 |

"知道某条线索" = 它在 `know` 里，或在 `runClues` 里。

## 2. 一轮的流程

**开始一轮**：`runs` 加一；本轮状态重置为：背包空、货币 = 剧情的 `startMoney`、信念 = 2、其余为空；然后进入起点。

**进入节点**：
1. `node` 设为该节点；节点不存在时，这一轮以"迷失"结束（`end.type = 'lost'`）。
2. `t` 加上节点的 `time`，`path` 追加该节点。
3. 如果是死亡或结局节点，这一轮结束：
   - 死亡节点有 `deathClue` 时：如果之前不知道，记为 `newDeathClue`；加入 `runClues`。
   - `runClues` 全部并入 `know`（这就是"失败有意义"）。
   - `total` 加上本轮的 `t`。
   - `end = { type: 'death' | 'ending', true: 是否真结局 }`。
   - `history` 追加 `{ run, title, kind: '死亡' | '真结局' | '坏结局', t }`。

一轮结束后，玩家可以刻下一句残响（见 5.3），然后开始下一轮。

## 3. 选项

### 3.1 选项的状态

当前节点的每个选项都有三个状态，互相独立：

| 状态 | 条件 | 玩家看到什么 |
|---|---|---|
| 隐藏 hidden | 有知识锁 `needClue`，且还不知道这条线索 | 看不到这件事 |
| 已用 used | `once` 为真，且本轮已经做过（记作 `节点id:选项序号`） | 这件事从场景里消失 |
| 锁定 locked | 道具不够（背包里 `needItem` 的数量 < `needQty`）或货币不够（`money` < `costMoney`） | 看得到，但做不了，并告诉玩家缺什么 |

知识锁的选项，在知道之后会出现；道具和货币锁的选项，一直看得到。

### 3.2 执行一个选项

按顺序检查，任何一项不满足就失败，状态不变：

| 检查 | 失败原因 |
|---|---|
| 这一轮已经结束 | `ended` |
| 选项不存在 | `missing` |
| 隐藏 | `hidden` |
| 已用 | `used` |
| 锁定 | `locked` |

通过后：
1. 一次性选项记入 `used`。
2. 结算背包：如果 `useItem`，背包里的 `needItem` 减去 `needQty`（减到 0 就移除）；`money` 减去 `costMoney`；获得 `gainQty` 个 `gainItem`；`money` 加上 `gainMoney`。
3. 有 `gainClue` 时加入 `runClues`。
4. `lastChoice = { node, idx }`。
5. 时间和去向：
   - 目标就是当前节点（"留在原地"的行动，例如打工、摸硬币）：`t += 6 + 当前节点的 time`，不进入新节点，`path` 不变。
   - 否则：`t += 6`，然后进入目标节点（第 2 节）。

常量：每次行动本身花 **6 秒**；每轮 **2 点**信念。

## 4. 场景物件

选项在场景里表现为可以走近、按空格互动的物件。

- **分组**：同一节点里 `obj`（去掉首尾空白后）相同的选项合并成一个物件；`obj` 为空的选项各自是一个物件。物件按其第一个选项出现的顺序排列。
- **互动**：物件里只剩一个可见选项时，直接执行；有多个时，弹出菜单让玩家选。全部选项都已用过的物件消失；全部选项都隐藏的物件显示为一团看不懂的雾。
- **外观**：组里任一选项写了 `look` 就用它；否则按物件名推测（含"门"→ 门；含"人 / 老板 / 醉汉 / 神父 / 修女 / 守夜 / 她 / 他 ..." → 人物；含"路 / 口 / 楼梯 ..." → 路标；含"书 / 桌 / 墙 / 蜡烛 / 钥匙 ..." → 物品）；再否则按第一个选项的文字推测。具体关键词以 `src/core/run.js` 的 `objectKind` / `looksOfText` 为准。
- **位置**：组里任一选项写了 `pos`（3–97）就用 `pos / 100`；否则第 `k` 个物件（共 `n` 个）放在 `0.24 + 0.68 × k / (n − 1)`，只有一个时放在 0.58。数值是占场景宽度的比例。

## 5. 残响

### 5.1 相信

每个场景最多同时飘过若干条残响。相信第 `k` 条：
- 本轮在这个场景已经相信过它 → 失败 `already`
- 信念为 0 → 失败 `no-belief`
- 否则：记入 `believed[节点]`，信念减一；残响带 `teach` 线索时加入 `runClues`。

相信过的残响会在它指向的选项上留下标记：任一相信过的残响推荐它 → "推荐"；否则有警告 → "警告"。

### 5.2 点赞

玩家可以给任何残响点赞或取消点赞，只改变点赞数，不影响规则。点赞数只决定残响被看到和被相信的可能（在模拟里），玩家看不到真假。

### 5.3 刻下残响

一轮以失败结束（死亡或坏结局）后，玩家可以在最后做选择的场景（`lastChoice.node`）刻一句残响：选一个选项，说"别这么做"（`avoid`）或"就这么做"（`go`），可以写一句话，留空时自动生成。

真假自动判定：那个选项通向死亡、坏结局或不存在的节点，算"坏"。说"别这么做"且确实坏、或说"就这么做"且确实不坏，就是真话。

## 6. 存档

存档保存两层状态的全部字段（集合存为数组，背包存为 `[道具, 数量]` 对），外加剧情的 `id` 和 `revision`。读档时：
- 跨轮记忆只保留剧情里仍然存在的线索；
- 只有剧情 `id`、`revision` 都相同，且所在节点仍然存在时，才能接着这一轮；否则保留跨轮进度，开始新的一轮。

格式以 `src/core/save.js` 为准，版本号 `v = 1`。

## 7. 不属于规则的部分

以下由各平台自己决定，不需要两边一致：画面、动画、音效、移动速度、键位、菜单样式、文字逐字显示的速度、台词怎么推进。

正文怎么拆成台词（`docs/STORY_FORMAT.md`「台词」）两边要一致，用例在 `tests/vectors/dialogue/`。
